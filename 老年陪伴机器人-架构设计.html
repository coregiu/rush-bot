SYSTEM DESIGN · V0.1

老年陪伴机器人
系统架构 · 技术栈 · 硬件选型

面向独居/空巢老人的室内陪伴机器人：语音问答与生活提醒、自主移动与定点递送、本地视觉跌倒监测并联动子女告警。

一句话定位：不是"保姆型人形机器人"，而是一台 会自己走动的"语音管家 + 安全哨兵 + 定点物流小车"。MVP 阶段把"帮老人拿东西"务实降级为"定点托盘递送"，不做通用机械臂抓取。
老人端零操作（语音为主） 告警低漏报 / 极低误报 视频本地处理，隐私不出户 毫米波兜底夜间/无灯看护 经济型 BOM < ¥3,500 移动限速 < 0.5 m/s，硬件急停
01

产品边界与核心场景

先划清"做什么 / 不做什么"，避免功能膨胀
  • 做：语音问答与闲聊、生活常识/用药提醒、日程提醒、跟随/定点递送物品、跌倒/异常检测、一键呼叫子女。
  • 不做（MVP）：通用机械臂抓取任意物体、做饭/倒开水、医疗诊断、室外移动、上下楼梯。
  • 用户：老人侧（70+，以语音交互为主）；子女侧（30–50 岁，用微信小程序收告警、看日报，不用装 App）。
  • 核心矛盾：技术上"抓取/行走"都可做，但家庭环境杂乱 + 老人配合度低 + 安全风险高，可靠性比功能丰富重要十倍。

三条核心链路

语音对话 / 跌倒告警 / 取物递送
链路 A · 语音问答与陪伴
本地兜底，弱网可用；只有复杂问答才上云。
唤醒词本地 KWSopenWakeWord
声源定位+VAD麦阵列波束6-Mic
ASR 识别本地优先sherpa-onnx

生成回答本地小模型 / 云端LLM+RAGQwen3B / DeepSeek
TTS 播报慢语速老人音色Piper
链路 B · 跌倒检测与子女告警（最高优先级）
多传感器融合 + 机器人到场语音确认，避免"狼来了"。
视觉+毫米波+声学融合姿态/呼吸/重物声YOLO+LD2410
导航走到身边Nav2 自主移动<0.5m/s
语音询问"您能动吗？"15s 等待
老人说"没事"→ 解除并记录本地
无回应 / 无法起身声光警示LED+蜂鸣
推送子女小程序+截图+视频WebRTC 呼叫

隐私：视频本地推理，仅告警事件上传 10 秒片段；60GHz 毫米波不成像、不拍画面，可作摄像头关闭/夜间时的兜底看护，老人/子女侧均明示告知。

链路 C · "帮拿东西"（务实降级方案）
MVP 不做机械臂，做"定点托盘物流"与"跟随递送"。
语音指令"把药盒送到卧室"slot 槽位
建图点位厨房/客厅/卧室Nav2 固定点
升起托盘电动推杆lift tray
自主导航超声波+雷达避障Nav2
到达播报"东西放这儿了"TTS
自动回充低电量回坞charging dock

模式 B：按托盘上按钮 → 机器人跟随老人行走，随时取放；V2 再探索轻量协作臂 + VLA 抓取指定物品。

07

关键风险与 MVP 路线

先把"安全哨兵"做扎实，再谈"智能"

跌倒检测误报率

单次误报就消耗子女信任，三次误报后告警被无视。

对策：视觉+声学融合，到场语音二次确认，无回应才升级。

"拿东西"预期落差

老人/子女期待"从桌上抓水杯"，现实做不到。

对策：宣传与产品定义统一为"定点递送/跟随托盘"，不承诺抓取。

老人不愿跟机器人说话

陪伴类产品最大死因不是技术，是老人弃用。

对策：主动发起（定时提醒/闲聊），一个物理大按钮兜底，音色温和。

摄像头隐私合规

家里有摄像头，老人/子女都会有顾虑。

对策：视频本地推理不出户，仅告警事件上传片段，明示同意+物理遮罩。

P0 · 8 周MVP 跑通

差速底盘 + Nav2 建图导航 + 语音问答/提醒 + 物理呼叫按钮。不做跌倒检测。

P1 · 12 周安全哨兵

本地视觉跌倒检测 + 到场确认 + 微信小程序告警推送 + 自动回充。这是产品卖点。

P2 · 16 周递送 + 打磨

定点托盘物流 + 跟随模式 + RAG 生活常识库 + 老人 UX 调优（大字号/慢语速）。

V3 · 探索机械臂 / VLA

仅在 P1/P2 验证可靠性后，再评估轻量协作臂 + VLA 抓取指定物品。
